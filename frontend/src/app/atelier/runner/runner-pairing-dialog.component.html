Connecter une machine

Le runner tourne sur votre machine et ouvre lui-même la connexion vers cette passerelle : aucun port à ouvrir en entrée — il lui faut en revanche une sortie HTTPS, que l'étape 1 vérifie. Il s'affiche en clair et s'arrête au Ctrl-C. Projet appairé : {{ data.workspaceName }}.

1 Vérifier l'accès réseau

Le runner sort vers cette passerelle en HTTPS : rien n'est à ouvrir en entrée, c'est le sortant qui bloque sur un poste d'entreprise. Cette page ne peut pas le vérifier à votre place — un navigateur ne lit pas la configuration proxy du poste. Collez cette commande dans le terminal où vous lancerez le runner.

{{ networkCheckCommand }}
  • 200

    Ce terminal atteint la passerelle.

    Poursuivez à l'étape 2.

  • 407

    Un proxy répond et exige une authentification.

    Si elle est intégrée (NTLM ou Kerberos), le runner ne pourra pas la porter : la JVM n'a aucun support SSPI, et l'authentification Basic est désactivée sur les tunnels HTTPS depuis Java 8u111. Le remède est un relais local — px ou cntlm — qui porte l'authentification intégrée et expose, lui, un proxy sans authentification. Une fois lancé, déclarez-le dans le terminal :

    {{ relayExportCommand }}
  • —

    Aucun code, ou could not resolve host / failed to connect.

    Le proxy de votre poste n'est pas déclaré dans ce terminal : il l'est côté système, et un shell ne le lit pas. C'est pourquoi votre navigateur atteint cette page alors que la commande échoue. Retrouvez-le :

    {{ proxyDiscoveryCommand }}

    Puis déclarez-le, avant de lancer le runner :

    {{ proxyExportCommand }}
